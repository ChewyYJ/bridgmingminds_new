# Read Aloud acoustic assessment implementation

Status: the server-only continuous SDK adapter, bounded decoder, private recoverable jobs and opt-in feedback UI are implemented and tested with offline transports. Real WebM, Ogg, MP3, fragmented MP4, native-style M4A and WAV conversion now pass local integration tests. Live Azure and actual native-device validation remain unverified. Read Aloud still qualifies through its explicitly authorised self-review fallback; optional acoustic feedback is a separate request and changes no rewards.

`server/speech-assessment.mjs` defines the initial capability contract and validates Azure pronunciation result segments. The initial assessment-locale allowlist is en-US/en-GB; it is intentionally narrower than general speech transcription availability. Locale must be a user-selected practice target, not an inferred judgment that Singapore English is incorrect. Prosody must be explicitly requested and is permitted only for en-US. Missing metrics are null. Recognition confidence is retained separately from pronunciation observations.

The continuous path is required for the two-minute reading activity. Single-utterance assessment is limited to 30 seconds; it must not silently truncate a longer take. The application bounds continuous recordings at 180 seconds. Continuous results do not support provider EnableMiscue, so completeness and omission/insertion feedback are withheld until a separately validated reference-alignment implementation exists. Utterance scores remain attached to their original segments. No invented overall average, intelligibility score, mastery update or XP decision is produced.

Validated words retain audio timestamps and ordered exact-token passage offsets, including Unicode offsets. Unmatched words have no passage highlight. Provider observations are explicitly unvalidated, not confirmed learner errors or objective accent judgments. NoMatch/silence is distinct from an assessment with missing fields. Invalid score ranges, confidence values, error states and timelines fail closed with a safe error.

Sources checked on 12 November 2026: [Microsoft pronunciation assessment documentation](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment) and [short-audio REST documentation](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short). The continuous SDK path is necessary for normal passages; short-audio REST alone cannot meet the product requirement.

## Configuration and request flow

The installed server-only SDK is locked at 1.53.0. Its current JavaScript prosody API is a boolean setter, rather than the method shown in some provider examples; the installed-API smoke test checks this without opening a connection. No SDK code or credentials are imported by the mobile app.

Set `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION` on the backend. Install FFmpeg on the backend host or set `FFMPEG_PATH` to its executable. This process needs a Node worker/function with enough execution time and support for a subprocess; a cloud SDK credential alone does not supply a media decoder. The decoder restricts input demuxers and protocols, never invokes a shell, and bounds bytes, output duration and execution time. WebM/Ogg/MP3/WAV conversion uses pipes. MP4/M4A uses an owner-only temporary input because ordinary native recordings may store seek-dependent metadata at the end. Copies live in unique 0700 directories with 0600 files, are removed in finally on completion/failure/timeout/cancellation, and are never exported or treated as retained recordings. Maintenance and subsequent conversions remove crash copies older than one hour. Set SPEECH_TMP_DIR to a private writable directory outside the source checkout; use an encrypted host volume where required. FFmpeg external MOV track references and remote protocols are disabled. PCM 16-bit mono 16kHz WAV uses a strictly validated direct path. Other WAV variants and browser/native compressed files use FFmpeg.

Apply additive migration `supabase/migrations/202611120002_speech_jobs.sql` before hosted deployment. Its table has RLS, no direct client grants, unique attempt references and deletion cascades. It has not been applied to a live database.

After saving a reading with private audio, the optional panel asks for an explicit practice target and permission to send that recording and reference passage to Microsoft Azure. Requests pin those settings. POST `/api/read-aloud/attempts/:id/speech-assessment` creates or safely retries the same job; GET on the same path restores it. GET `/api/read-aloud/speech-jobs/:id` checks progress and can recover delayed processing using a database lease. Maintenance processes one pending speech job per run. Retries are explicit, with three provider-failure attempts, ten admitted acoustic requests per user/week and the shared daily provider cap. These do not reserve weekly speaking-practice slots or block self-review.

The worker checks ownership, retention and current recording consent before decoding, before transmission and before saving. Withdrawal or deletion prevents result persistence. Jobs store validated results alongside the attempt and its reading-session snapshot, separately from self-review evaluation. They are exported and cascade on account deletion. Results never grant XP, mastery or garden growth. A no-speech acoustic result cannot manufacture scores; the earlier self-review remains explicitly self-reported participation.

The feedback panel shows per-utterance metrics, aligned passage highlights, paginated word inspection and timing-linked private playback. Green indicates alignment; yellow indicates a provisional provider review suggestion. Retry/error states preserve the recording. Reload restores completed results. Prosody support is present in the server adapter, but the current UI requests accuracy/fluency without prosody.
